## 2. 先对齐的资金与节奏方案

### 2.1 净资产口径

建议采用可解释的账面成本口径：

**净资产 = 可用现金 + 未到期投资的投入本金 − 未偿贷款的全部应付金额。**

- 起始现金 100；放弃核心多拿 30，则初始现金 130。这部分真实现金计入净资产。
- 永久商品和消耗品不作资产计价；购买会降低净资产。
- 投资投入只把现金换成锁定本金，不创造财富；未到期收益不提前计入。
- 股票和债券未到期按投入本金记账，不读取私有随机结果提前估值，到期才确认损益。
- 借 40、到期还 50，借入时现金增加 40、应付债务增加 50，净资产减少 10；还款时债务清除，不重复计利息损失。
- 原价回购返还一件实际买入成本，现金及净资产上升，立即检查 500 目标。
- 追偿、手牌奖励和投资到期收益均只入账一次，不把本金返还误记为全部投资利润。

例：现金 100，存入 30 后为现金 70 + 投资本金 30 = 净资产 100；到期返 40 后，净资产成为 110。现金 100 借入 40 后，净资产为 140 − 50 = 90。

胜利在完整的一轮结算结束或下注前回购等合法现金动作后检查；不在一手牌尚未结算时用临时现金提前结束。

胜利时按成本清算未到期本金、支付已计入的剩余债务，不给尚未实现的利息，最终结算现金与判胜净资产一致。失败时不允许凭空推进回合等待到期，不提前赎回投资救命。（已确认。）

### 2.2 最低下注与商店节奏

保留最高下注为可用现金一半；永久增益位 3 个，同名不重复，满位可替换。（实现时改为 2 个。）

| 回合 | 最低下注建议 | 自由格永久商品概率 |
|---|---:|---:|
| 1–3 | 5 | 20% |
| 4–6 | 10 | 30% |
| 7–9 | 15 | 40% |
| 10–12 | 20 | 40% |
| 13–15 | 30 | 40% |
| 16–18 | 40 | 40% |
| 19 起 | 每三个回合再增加 10 | 40% |

商店基准 3 格，金融核心增加到 4 格；每两轮补货；每批一格优先泛用消耗品，其他格按类别和流派权重选。当前核心权重 ×2，无核心无偏向。库存不足时补其他合法商品。

每批保留一次普通付费刷新，固定 3 筹码；优先换货另提供一次免费刷新。刷新编号进入独立随机种子，不沿用当前仅 bool 的重复种子，不因读档或重新装备重置。

最低下注增长不同时推动商品涨价。先用固定报价，便于判断回本与替换成本，后续模拟再判断是否需要阶段价格。

继续沿用发牌后、玩家行动前的 Chaos 时机，避免第一版同时改下注与发牌流程。

建议每轮最多新增一条或平静；不同规则跨回合保留，同名不重复叠数值，暂设最多 **3 条**。满位时不再新增，移除后空出位置。该上限、同名处理及平静频率待对齐，不把它们写成既定效果。

静默印章仅压制当轮，不删除存储的规则。天然开局判定使用实际两张起手牌，近似满点不进入天然步骤。

## 4. 实施顺序与验收

### 阶段 A：状态、账本与兼容入口

- 注册新构筑桌，建立目录、版本化状态、统一净资产和终局检查。
- 保存核心候选、逐件买价、刷新计数、未到期合同等，不靠 GUI 临时变量保存。
- 旧 Poker Head 存档无构筑状态时保留原目标和玩法，不自动塞核心或改成 500。
- 新构筑通过 --mode chaos 进入；旧的无模式 --chaos 保留兼容，具体是否统一入口再对齐。
- 下注前冻结牌序及未来股票私有结果只能保存在私有状态，不能泄露到公开 agent observation 或通用 GUI view。
- 每阶段都支持存档，未知旧字段按兼容路径处理。

验收：买存款净资产不变，借款不触发胜利，同一金额不重复记账，旧档和另外两张桌仍按旧逻辑运行。

### 阶段 B：核心、商店和装备替换

- 开局随机二选一与拿资金退出、改约函、三位装备与替换确认。
- 加权概率、已装备排除、金融额外格、采购折扣、免费刷新计数。
- 满位购买一次确认后才扣款；拒绝、非法目标和取消不改变状态。
- 逐件记录折扣后的实际买价，金融投入本金不套采购折扣。

验收：换核心不清装备，换出再换回不能刷次数或货架，候选与货架可复现。

### 阶段 C：手牌与回合效果

- 统一玩家/庄家手牌评价，UI、实际胜负、窥牌与危险预测共用同一评价。
- 多牌奖励、J/Q/K=5、余裕爆牌线、近似满点、满点彩金。
- 开局先应用败后王牌，再检查真实天然，借花献佛优先转移庄家天然胜利。
- 投降减损、追偿资格、免赔互斥、加倍资格与风险分担、明牌审计。
- 最终手牌 delta 在更新现金和生成 RoundResult 前确定；本金到期等账本事件单独记明来源。

验收：实际22先映射再判爆牌；投降后的下一轮起手A可以自然组成天然；追偿按上轮未折扣金额；免赔不追偿；四倍损失减25%。

### 阶段 D：消耗品、预言和持续规则

- 所有道具逐件校验使用阶段与目标，下注前可用的不依赖已有手牌状态。
- 命运预言与下注共用同一冻结牌序，纯购物/刷新不重洗；改牌、搬牌明确刷新或失效提示。
- A 置顶、撤牌、换牌、定向解除、暂停与爆牌线准备。
- 原价回购按具体库存实例返现并即刻判胜。
- 持续规则与本轮暂停分开存储，清除和新一轮恢复不会丢失或复制规则。

验收：公开观察不泄露预言之外的未来牌，失败使用不扣道具，回购可无需新下注直接通关。

### 阶段 E：金融到期、清算与公开界面

- 逐笔合同期限、条件、独立股票随机流、强制还贷、收益加成。
- 到期先处理本轮所有已确定的资产和债务，再做终局检查，资金不足不能借新还旧。
- 新增 poker_head.core / loadout / wallet / finance / preparations / choices 信息部件。
- 使用现有 Layout、Rows、ListWidget、Progress、Act 展示资金目标、候选和替换对象；保留现有中央牌桌。
- 商店需要少量通用改造：动态三/四格、类别、描述、买入或替换目标。背包需要逐件 enabled，而非仅一个全局 USE_ITEM。
- Agent CLI 和流式 API 增加同源选择动作、目标参数及公开净资产/装备/合同摘要；更新指南和 schema 兼容说明。

验收：GUI 与 agent 的合法动作一致，按钮阶段正确，核心选择和换装取消不花钱，净资产进度明确区分现金与投资债务。

### 阶段 F：回归与定价验证

- 离线单元和场景测试：上述边界、存档复现、模式隔离、英文界面文案和无账本重复入账。
- 全部完成后跑 python -m pytest。
- 独立 black-jack-sim 的 bjsim/adapter.py 适配新增能力，先用 python -m bjsim check 检查旧回归。
- 新增五种构筑及混合策略实验；现有基础策略不会主动构筑，不能拿旧 bot 的结果宣称新玩法平衡。
- 对比胜率、构筑成形轮数、局长、花费、永久商品购买与替换率、不同流派收益及“只投降买定存”策略。
- 调整先落在克隆的实验余额档，再更新交付种子；旧规则回归带与新玩法指标分开维护，不为掩盖错误放宽旧指标。
- 所有测试与模拟禁用 billed LLM，不用真实模型来决定金融随机结果。
